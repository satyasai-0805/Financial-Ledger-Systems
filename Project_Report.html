1. Introduction & Objective

1.1 Problem Statement

Small and medium enterprises in India often rely on manual bookkeeping or spreadsheet-based systems for financial record keeping. These approaches are error-prone, lack audit trails, and do not enforce the fundamental accounting equation: Assets = Liabilities + Equity.

1.2 Objective

The objective of this project is to design and implement a fully functional, enterprise-grade Double-Entry Financial Ledger System that:

  • Enforces the double-entry bookkeeping principle where every transaction must have equal debits and credits.
  • Maintains ACID-compliant transactional integrity using PostgreSQL.
  • Produces standard financial reports: Trial Balance, Profit & Loss Statement, and Balance Sheet.
  • Uses General Ledger (GL) Code nomenclature for professional chart-of-accounts identification.
  • Supports the Indian Financial Year (April 1 – March 31) with automatic date validation.
  • Adheres to IAS 8 / Ind AS 8 accounting immutability standards (no modification or deletion of posted entries).
  • Provides a modern, responsive web interface with intelligent data-entry automation.

1.3 Scope

The system covers the complete lifecycle of financial transaction processing:

  • Account creation and management with GL codes
  • Transaction posting with real-time double-entry validation
  • Automated report generation (Trial Balance, P&L, Balance Sheet)
  • Intelligent form auto-population with Quick Templates
  • Historical transaction cloning for repeating entries
  • Persistent PostgreSQL storage with automatic schema management

4. Database Design

4.1 Entity-Relationship Model

The database consists of three core tables following double-entry bookkeeping principles:

Relationship: One Transaction has many JournalEntry records (1:N). Each JournalEntry references exactly one Account (N:1).

Table: accounts

5.2 Core Business Rules

  1. Double-Entry Enforcement: Every transaction must contain at least 2 journal entries. Total Debits must exactly equal Total Credits, verified to 2 decimal places.
  2. Financial Year Validation: The system dynamically computes the active Indian Financial Year (April 1 – March 31). Transactions outside this period are rejected with HTTP 400.
  3. Audit Immutability: Per IAS 8 / Ind AS 8 standards, no PUT, PATCH, or DELETE endpoints exist. Errors are corrected via reversing journal entries only.
  4. Amount Precision: All monetary amounts are stored as NUMERIC(19,4) and normalized to 2 decimal places with HALF_UP rounding.

7. Key Features

7.1 Auto-Balance Entry

When journal entry legs are unbalanced, clicking "🪄 Auto-Balance Entry" instantly appends a new row with the opposite type (DEBIT/CREDIT) and the exact difference amount pre-filled, along with a pre-selected balancing account.

7.2 Real-Time Search & Filter

A search bar above the Transaction Ledger Logs table performs instant client-side filtering across narration description, account name, account type, and transaction ID without any network request.

7.3 Strict Accounting Immutability

In compliance with IAS 8 / Ind AS 8, no PUT, PATCH, or DELETE endpoints are exposed. All corrections must be made via reversing journal entries, maintaining a complete audit trail.

7.4 Financial Year Date Constraint

The system dynamically computes the active Indian Financial Year (April 1 – March 31). Transactions outside this range are rejected with a clear error message.

7.5 Financial Reports

  • Trial Balance: Two-column debit/credit layout with structural verification badge.
  • Profit & Loss: Revenue vs. Expense summary with Net Profit/Loss indicator.
  • Balance Sheet: Assets vs. Liabilities+Equity with accounting equation verification.

7.6 Quick Templates & Smart Auto-Detection

One-click template buttons (🏢 Rent Invoice, 💸 Pay Rent, 🔌 Utility Bill, etc.) instantly fill the narration, select the correct debit/credit accounts, and auto-focus the amount field. Additionally, as the user types a narration, intelligent keyword detection automatically adjusts the account selectors in real time.

7.7 Transaction Cloning

A "Use Template" button next to each historical transaction in the ledger table clones the transaction's description, accounts, and debit/credit types into the form for quick repeating entries.

7.8 GL Code Integration

Accounts are identified by standard General Ledger codes (1000 for Cash, 2000 for Liabilities, 4000 for Revenue, etc.) rather than sequential database IDs, following professional accounting nomenclature.

7.9 PostgreSQL Persistence

All data is persisted in a production-grade PostgreSQL database with Hibernate ORM handling automatic schema management, foreign key constraints, and ACID transaction compliance.

9. Deployment & Execution Instructions

9.1 Prerequisites

  • Java JDK 17+ installed
  • Node.js 18+ and npm installed
  • PostgreSQL installed and running on port 5432
  • A database named ledger_db created in PostgreSQL

9.2 Start the Backend Server

cd D:\Projects\financial-ledger-system\backend-server

D:\Projects\financial-ledger-system\apache-maven-3.9.6\bin\mvn.cmd ^
  spring-boot:run ^
  -Dspring-boot.run.arguments=--spring.config.location=file:../database-server/application.properties

The backend will start on http://localhost:8080.

9.3 Start the Frontend Client

cd D:\Projects\financial-ledger-system\frontend-client

npm run dev

The frontend will start on http://localhost:5173.

9.4 Database Configuration

Connection settings are in database-server/application.properties:

spring.datasource.url=jdbc:postgresql://localhost:5432/ledger_db
spring.datasource.username=postgres
spring.datasource.password=2006
spring.jpa.hibernate.ddl-auto=update

11. Conclusion & Future Scope

11.1 Conclusion

The Enterprise Double-Entry Financial Ledger System has been successfully designed, implemented, and validated as a full-stack web application. It enforces the fundamental principles of double-entry bookkeeping with ACID-compliant PostgreSQL persistence, produces standard financial reports (Trial Balance, Profit & Loss, Balance Sheet), and provides an intelligent, modern user interface that dramatically reduces data-entry effort through Quick Templates, keyword-based auto-detection, and transaction cloning.

The system adheres to Indian accounting standards (Ind AS 8) for immutability and supports the Indian Financial Year calendar. General Ledger codes provide professional chart-of-accounts identification consistent with enterprise ERP systems.

11.2 Future Scope

  • Multi-User Authentication: Add Spring Security with JWT-based login and role-based access control (Admin, Accountant, Auditor).
  • Multi-Currency Support: Extend the system to handle transactions in multiple currencies with real-time exchange rate conversion.
  • PDF Report Export: Generate downloadable PDF versions of Trial Balance, P&L, and Balance Sheet reports.
  • Audit Log Trail: Maintain a separate immutable audit log recording all user actions with timestamps and IP addresses.
  • GST Integration: Add Indian Goods & Services Tax calculation and GSTR return preparation.
  • Cloud Deployment: Deploy the application on AWS/GCP with managed PostgreSQL (RDS/Cloud SQL).
  • Data Visualization: Add interactive charts and graphs for revenue trends, expense breakdowns, and cash flow analysis.
  • Recurring Transactions: Support automatic scheduling of periodic entries (monthly rent, salaries, etc.).
Project Status: All planned features have been implemented, tested, and validated successfully. The system is fully operational and ready for production use.
